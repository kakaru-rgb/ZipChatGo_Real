“부동산 중개업자처럼 말하게 한다”는 것은 학습이 필요 없다"
-> OpenAI API에 developer/system instructions를 넣으면 됩니다.
-> Developer Prompt 작성 요망
예)
- 공인중개사처럼 정중하고 전문적으로 설명한다.
- 어려운 부동산 용어는 쉽게 풀어서 설명한다.
- 매물을 무조건 추천하지 않는다.
- 장점뿐 아니라 위험요소도 함께 설명한다.
- 법률 관련 답변에는 근거를 제시한다.
- 확실하지 않은 내용은 단정하지 않는다.
- 투자 수익을 보장하는 표현을 사용하지 않는다.

Developer Prompt

당신은 대한민국 부동산 시장을 전문적으로 상담하는
AI 부동산 상담사입니다.

말투는 전문적인 공인중개사의 상담 스타일을 사용합니다.

사용자의 요구사항을 먼저 정확히 파악하고
조건에 맞는 정보를 설명하십시오.

법률 관련 질문에는 반드시 제공된 법령 자료를 검색하고
근거가 없는 내용을 만들어내지 마십시오.

2) RAG
부동산 법 수집
주택임대차보호법.pdf
상가건물임대차보호법.pdf
공인중개사법.pdf
민법_임대차.pdf
부동산거래신고법.pdf
주택법.pdf
국토계획법.pdf
...

이것이 RAG(Retrieval-Augmented Generation)입니다.

OpenAI API 자체에도 Vector Store와 File Search 기능이 있어서, 파일을 Vector Store에 넣고 사용자의 질문과 관련된 부분을 검색할 수 있습니다.

따라서 초기 버전에서는 Pinecone, Chroma, FAISS 같은 것을 반드시 별도로 설치할 필요조차 없습니다.


| 목표           | 방법                 |
| ------------ | ------------------ |
| 중개사처럼 말하기    | **Prompt**         |
| 상담 순서와 태도    | **Prompt**         |
| 부동산 법률 지식    | **RAG**            |
| 최신 법률 반영     | **RAG 문서 업데이트**    |
| 실제 매물 검색     | **DB Tool/API**    |
| 계산           | **Function/Tool**  |
| 매우 일관된 특수 말투 | 나중에 Fine-tuning 고려 |

결국 당신이 만들려는 AI는 이런 구조가 됩니다
제가 이 프로젝트를 단계적으로 만든다면 다음 순서로 갑니다.

1. GPT-5.6 Terra API 연결
2. 우선 일반적인 대화가 가능하게 만듭니다.
3. 부동산 중개사 Developer Prompt 작성
4. 말투, 상담 절차, 금지사항, 질문 방식 등을 정의합니다.
5. 부동산 법률 PDF 수집
6. 가능하면 국가법령정보센터 등 공식 원문을 기준으로 관리합니다.
7. 법률 RAG 구축
8. OpenAI Vector Store + File Search부터 시작합니다.
9. 출처 표시
10. 법률 답변에는 법률명, 조문, 기준일 등을 보여주도록 합니다.
11. 매물 DB 연결
12. 이후 실제 백엔드가 만들어지면 DB 검색 Function을 추가합니다.
13. 지도와 AI 연결
14. 현재 지도 영역, 선택 지역, 줌 범위 등을 AI에게 context로 전달합니다.
15. Agent로 확장
16. AI가 RAG, 매물 검색, 실거래 검색, POI 검색 등을 스스로 선택하도록 합니다.

첨부한 `real_estate_ai_agent_development_plan.txt`를 이 프로젝트의 AI Agent 개발 기준 문서로 사용해줘.

앞으로 작업은 이 문서의 방향과 순서를 최대한 유지해서 진행하고 싶다. 한 번에 여러 단계를 건너뛰지 말고, 각 단계별로 현재 코드 구조를 먼저 확인한 뒤 필요한 파일과 수정 범위를 설명하고 구현해줘.

우선은 문서의 `[0단계] 현재 웹사이트 정리`부터 시작하자.

현재 프로젝트를 분석해서:

* 어떤 페이지가 있는지
* 지도 관련 기능이 어디에 구현되어 있는지
* 매물 검색/상세/관심매물/분석 기능이 어디에 있는지
* 향후 AI Tool로 만들 만한 기존 함수와 API가 무엇인지
* AI Agent 연결 전에 정리하거나 보완할 부분이 무엇인지

먼저 정리해줘.

아직 다음 단계 구현은 시작하지 말고, 0단계 분석 결과부터 보여줘.

지금까지 완료한 내용을 기준 문서와 비교해서 어떤 단계까지 끝났는지 정리하고, 다음 단계에서 해야 할 일을 알려줘.

라고 하면 좋습니다.
